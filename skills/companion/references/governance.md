# Weekly value review and monthly structure audit

Review how well this profile serves its user. Consider verified outcomes alongside model/tool spending, coordination, attention and time to a useful result. Prefer simpler work and reusable results where the evidence supports them. Do not equate generated output, task counts or more agents with value.

The weekly review looks back seven days at outcomes, wasted effort, next-week adjustments and useful reuse. The monthly audit looks back thirty days at priorities, instruction size, duplicated rules and whether responsibilities belong in the current document, skill, runtime or Cron. Use the user's own principles when available; do not require a new doctrine file or rewrite their identity.

## Evidence

Start with muse_manage status: reviews contains the latest weekly/monthly summaries, and installation_ref points to the owned-jobs projection. Use existing session search and native Cron execution/output records for history. Read only the relevant parts of current-profile instructions and actual user feedback. If usage/cost data or session history is unavailable, disclose that gap. Do not scan other profiles, connect to other machines, require an external notes service, read secrets, or copy private content into public artifacts.

These reviews may assess whether a relevant skill is being used well, but they do not run a separate skill audit, optimize all skills or replace Curator. Nightly maintenance already handles memory/alignment; weekly/monthly reports should avoid repeating it.

## Result and follow-up

Make the report as detailed as its findings require, with a clear lead and concrete evidence. Only the saved review_complete summary has the 2000-character limit; full findings stay in native output or a linked artifact. Use the user's language. Tie suggestions to evidence and identify the affected file, task or workflow when that helps a decision; avoid mechanical labels and a fixed number of bullets. Reports recommend changes; they do not apply them. A user can later choose a recommendation in conversation.

Save only the plugin's review summary/cursor via review_complete. Native Cron retains each run's full output and delivery record. The two scheduled reports go directly to this profile's Bot Chat; do not also use the ordinary proactive-notice queue. Bot Chat presents the findings directly to the user using the communication procedure, and the report never becomes a new user signal.

Defaults use the current Hermes timezone: weekly-governance-review runs Sunday at 21:15; monthly-system-audit runs on the first day of each month at 10:40. They are installed with the rest of the plugin. Existing unrelated review jobs remain user-owned.

Check source_checks for missed/partial reads and repeated failures, compare native run history with claimed coverage, inspect unfinished native research and final deliveries, and look for repeated notices or work continuing after closure. Inspect current last-complete/partial stage summaries, unprocessed user authority and selected consequential cases. Legacy raw history is explicitly unreviewed, not a requirement to catch up every event row. Evaluate persistent material failures, unverified completion claims, repeated work and whether important corrections were retained; do not use all-log throughput as value. Describe independent progress as well as the missing responsibility. Keep severe gaps in the user-facing summary; never grade scheduler success, silence or file freshness as full business completion. User-owned subscriptions are separate from these fixed jobs. Checking many sources and sending many messages are not success metrics. Weather/news selection follows the same value and evidence tests.

Evaluate rich useful content, reasoning quality, timely initiative, coverage/recovery, delivery and conversational responsiveness first. Consider reducing redundant work only when these outcomes are preserved. Fewer calls, shorter prompts and fewer reminders are not success criteria by themselves. Apply the recovery contract to missing evidence; do not silently grade incomplete coverage as healthy.
